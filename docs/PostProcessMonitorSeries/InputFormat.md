# 监控日志输入格式（草案）

> **状态：草案，随实际数据格式确认而演进。**
>
> 本文件描述 `MonitorLogReader` 当前**实际接受**的输入，以及为尚未见过的格式预留的扩展点。
> 之所以是草案：直到 2026-11-08，仓库里唯一有据可查的真实样本是 SU2 的 `history.csv`。
> 其余求解器的输出格式尚未取得样本，因此下文的"内置规则"不能当作行业约定，只能当作现状记录。
>
> 规范与代码的对应关系是单向的：**代码是事实来源，本文件是它的说明**。两者不一致时以代码为准，
> 并应修正本文件。

## 1. 为什么要有一份规范

列判定的规则原本只存在于 `MonitorLogReader.cpp` 的几个静态函数里。这带来三个具体问题：

1. 想知道"什么样的文件能被导入"，必须读源码，而且要把 `looksLikeResidual`、`unitForColumn`
   这类细节函数一并读完。
2. 规则写死为 SU2 形状。第二套命名只能靠改源码，而改动源码会影响所有既有调用方。
3. `canRead()`（探针）与 `readCsv()`（读取器）曾经各有一套判据，对同一文件可以给出不同结论。

本文件解决第 1 条，第 2、3 条由代码里的注册表与统一谓词解决（见第 6 节）。

## 2. 文件的准入条件

一个文件要被识别为监控日志，必须**同时**满足：

| 条件 | 说明 |
| --- | --- |
| 后缀为 `.csv` | 不区分大小写；其他后缀一律拒绝，不做内容嗅探 |
| 文件存在、是常规文件、大小 > 0 | |
| 表头至少有一个"可识别列" | 见第 4 节。这是**唯一的**内容判据 |

"可识别列"指满足以下任一条件的列：

- 是索引列（迭代步/时间），或
- 是残差列，或
- 单位已知（例如气动系数，单位记作 `-`）

判据的实现是单一谓词 `MonitorLogReader::hasRecognisedColumns()`，
`canRead()` 与 `readCsv()` 都调用它。**探针与读取器不允许给出不同结论。**

### 为什么拒绝"通用 CSV"

`a,b\n1,2` 这样的文件没有任何一列可识别。若接受它，读取器只能把某一列画在行序号上，
并称之为"求解器历史"——那是凭空捏造一条曲线。因此宁可拒绝并给出可读理由：

```
文件中没有可识别的监控列（迭代步、残差或气动系数），请确认这是求解器输出的 history 文件。
```

## 3. 文本编码

| 情况 | 处理 |
| --- | --- |
| 空文件 | 拒绝：`文件为空，没有可解析的监控序列。` |
| 含 \0 字节 | 拒绝：`文件包含二进制内容，不是纯文本监控日志。` |
| 非 UTF-8（解出 U+FFFD） | 拒绝：`文件不是有效的 UTF-8 文本，请先转换为 UTF-8 后再导入。` |
| 有 BOM | 静默剥除 |
| CRLF 行尾 | 静默剥除 `\r` |
| 完全空白的行 | 跳过，不计入数据行 |

**不猜编码。** 不尝试 GBK、Latin-1 或任何回退编码。猜错会得到一批看似正常、实际错位的数字，
比明确拒绝坏得多。

**两条读取路径使用同一套判定。** 上表对离线读取（`MonitorLogReader`）与实时跟随
（`MonitorFileTailSource`）都成立，错误文案逐字一致。实时路径的编码校验是字节级的
（`isUtf8()`），不是"解码后查 U+FFFD"——分块读取时一个多字节字符可能被两次读取劈开，
用解码结果判定会把正常的字符边界误报成编码错误。

实时路径的错误是**粘性**的：非文本文件不会自愈，报一次后每轮读取都重复同一条错误，
不会因为后续字节恰好能解析就恢复"健康"。

## 4. 列角色判定（内置规则）

判定**只看列名**，不看数值内容。

### 4.1 残差列

满足任一条件即为残差列，建议使用对数纵轴：

- 以 `rms` 开头（不区分大小写）
- 含 `residual`（不区分大小写）
- 以 `RMS[` 开头（不区分大小写）

### 4.2 索引列（轴列）

精确等于以下之一（不区分大小写）：

`Time_Iter`、`Outer_Iter`、`Inner_Iter`、`Iteration`、`Iter`

索引列不参与绘制，只用于提供横轴。

### 4.3 单位推断

| 列名 | 单位 |
| --- | --- |
| 残差列 | `-` |
| `CD` `CL` `CSF` `CMx` `CMy` `CMz` `CFx` `CFy` `CFz` `CEff` `CX` `CY` `CZ` | `-` |
| 以 `Coeff` 开头 | `-` |
| `Time_Iter` | `iter` |
| 其他 | 空（视为无量纲） |

单位靠**查表**得到，不是从数据推断的。这是当前实现的明确局限：真正的单位应来自求解器配置。
查表命中的列计入"可识别列"，未命中的列若同时不是索引列或残差列，则不计入。

无法推断单位的列不会导致失败，但会写一条警告：

```
下列列的单位无法推断，按无量纲处理：<列名列表>
```

### 4.4 横轴回退链

横轴按以下顺序确定，第一个可用者胜出：

1. `Outer_Iter`（当其确实推进时）
2. `Inner_Iter`（此时写警告 `Outer_Iter 未推进，迭代步横轴回退为 Inner_Iter。`）
3. 注册规则声明的主轴列（此时写警告 `迭代步横轴取自注册规则识别的列 <列名>。`）
4. 行序号（此时写警告 `文件没有迭代步或时间索引列，横轴将使用行序号。`）

第 4 条是**兜底而非正常路径**：行序号是编号，不是数据。任何能让真实步进列被认出来的手段，
都优先于行序号。

实时跟随路径实现同一条链，但规则换成增量式：它看不到整个文件，只能按已到达的行累加
"这一列变化了几次"，选定后即冻结（某列静止一百行后动一下，若允许重新判定会静默重编
所有曲线的横轴）。"暂定"与"确定"是两种状态——首批只有一行时看不到任何推进，
此时不冻结，留待后续投递判断。

## 5. 数据行解析

### 5.1 分隔与引号

- 分隔符固定为逗号。**不支持分号、制表符。**
- 双引号内的逗号不分割。
- **不支持转义引号**（`""` 表示一个字面引号）。表头含转义引号时解析会出错。

已知局限，当前夹具未触发。若后续真实数据出现，需要扩展 `splitCsvLineImpl()`。

### 5.2 容错分级

| 情况 | 处理 | 是否计入警告 |
| --- | --- | --- |
| 字段数少于表头 | 跳过该行 | 是（离线计入 `skippedRows`；实时另有 `skippedRows()`） |
| 字段数多于表头 | 截断到表头列数 | 是（字段数不一致行数） |
| 单元格非数字 | 填 `NaN` | 否（NaN 本身即断口） |
| 表头重复列名 | 保留第一次出现 | 是 |

**非数字填 NaN 而不是 0**，理由：填 0 会画出一条求解器从未报过的平线，把"没有数据"伪装成
"数值为零"。NaN 在曲线视图上是断口，如实反映缺失。

**离线与实时共用这同一张表。** 上表的判断只有一份实现：`MonitorLogReader::admitDataRow()`
决定一行是否可归属到列，`MonitorLogReader::parseNumericField()` 解析单元格。离线读取器与
实时跟随源都调用它们，不再各写一份。

这不是整洁问题。在这条规则统一之前，同一份文件在两条路径上会得到不同的序列：

| 分歧 | 离线（修复前） | 实时（修复前） |
| --- | --- | --- |
| 字段数少于表头 | 跳过该行并写警告 | 补缺失值照单全收，无警告 |
| 带引号的数字 `"0.25"` | 只 `trimmed()`，得 NaN | 剥引号，得 0.25 |

同一份坏文件，离线 79 行、实时 80 行；同一个单元格，一条路径读得出数字、另一条读不出。
两条路径汇合到同一个 `MonitorLog` 之后，这种差异不会再有任何提示。

实时源另有 `skippedRows()` / `raggedRows()` 两个查询给出**次数**。警告是去重后随投递下发的，
只能说明"发生过"；长跑的调用方要判断「偶尔一行坏」还是「整份格式不对」，需要次数。

### 5.3 数据行以外的拒绝

- 表头为空或全部列名为空：`表头为空或不含可识别的列名。`
- 没有任何可解析的数据行：`文件中没有可解析的数据行。`
- 只有索引列、没有可绘制数值列：`文件只有索引列，没有可绘制的数值列。`

## 6. 扩展点：注册非 SU2 的列约定

内置规则只覆盖 SU2 形状。**不去猜第二套格式**，而是把扩展点留出来。

```cpp
struct MonitorColumnRules {
    QString id;                                       // 稳定标识，如 "openfoam"
    QString description;                              // 供将来 UI 展示
    std::function<bool(const QString &)> isResidual;  // 建议对数轴
    std::function<bool(const QString &)> isAxis;      // 索引列，不绘制
    std::function<QString(const QString &)> unitFor;  // 空串表示未知
    std::function<bool(const QString &)> isPrimaryAxis; // 独立变量所在列
};
```

通过 `MonitorColumnRegistry::instance().registerRules(rules)` 注册。关键语义：

| 语义 | 说明 |
| --- | --- |
| **内置规则优先** | 注册的规则只处理内置规则未认领的列名。注册无法重新解释既有 SU2 表头。 |
| **未注册时行为完全不变** | 注册表为空时，读取行为与引入该机制前逐字节一致。 |
| **空成员不贡献** | 某个 `std::function` 未设置时，该类判定直接跳过它。 |
| **同 id 替换而非累积** | 重复注册同一个 `id` 会替换先前条目，便于重新配置。 |
| **进程级而非逐调用传参** | 规则描述的是**文件格式**，格式不随调用点变化。启动时配置一次。 |
| **不加锁** | 注册与读取之间没有同步。不要在其他线程正在读取时注册。 |

### 已知的扩展缺口

注册表覆盖列名判定与横轴选择，但**尚未覆盖**：

- 分隔符（固定逗号）
- 转义引号（不支持）
- 注释行（以 `#` 开头的行会被当作数据行）
- 编码（固定 UTF-8，不猜）
- schema 版本概念

这些若有真实数据出现，需要新增扩展点，而不是修改既有语义。

## 7. 警告与错误的完整清单

### 7.1 错误（导致读取失败）

```
内部错误：未提供 MonitorLog 输出对象。
无法打开文件：<路径>
文件为空，没有可解析的监控序列。
文件包含二进制内容，不是纯文本监控日志。
文件不是有效的 UTF-8 文本，请先转换为 UTF-8 后再导入。
表头为空或不含可识别的列名。
文件中没有可识别的监控列（迭代步、残差或气动系数），请确认这是求解器输出的 history 文件。
文件中没有可解析的数据行。
文件只有索引列，没有可绘制的数值列。
```

### 7.2 警告（读取成功，但有问题）

```
表头出现重复列名 <列名>，已只保留第一次出现。
已跳过 <N> 行无法解析的数据行。
<N> 行的字段数与表头不一致，已按表头列数对齐。
文件没有迭代步或时间索引列，横轴将使用行序号。
下列列的单位无法推断，按无量纲处理：<列名列表>
Outer_Iter 未推进，迭代步横轴回退为 Inner_Iter。
迭代步横轴取自注册规则识别的列 <列名>。
```

警告不会静默丢弃，全部进入 `MonitorLog::warnings`。

## 8. 当前唯一有据可查的真实样本

`tests/fixtures/postprocess/su2_history_steady.csv`：

- 来源：真实 SU2 求解输出（`history.csv`），2026-10-28 取得
- 取首 40 行与末 39 行，共 79 行数据，17 列
- `Time_Iter`、`Outer_Iter` 恒为 0（定常计算），实际推进的是 `Inner_Iter`（0 → 325）
- 因此横轴走回退链第 2 条，并产生对应警告
- `rms[Rho]` 取值为负（`-1.60335846` → `-8.008371149`），对数纵轴对它无效，视图须降级为线性
- 该文件在 `Inner_Iter` ≈ 40 与 ≈ 285 之间存在 248 步断档（裁剪导致，非求解器行为）

`tests/fixtures/postprocess/curves.csv` 是**反例**：单列气动系数表（`seriesId,caseId,x,yName,y...`），
不是监控日志，不得被本读取器认领。
