# 主窗口 Ribbon 分组调整验证

日期：2026-10-29。基础：主分支 `533e7ff`，叠加 Windows 中文文字修复。

## 界面与行为

采用 SARibbon 的 Office 三行样式（`RibbonStyleLooseThreeRow`），大按钮与三行小按钮混排。参考项目：https://github.com/czyt1988/SARibbon 。

| 页签 | 分组 |
| --- | --- |
| 开始 | 工程、批量管理、前处理、业务参数 |
| 监控 | 当前计算状态、运行监控 |
| 后处理 | 工作区、场显示、结果展示 |
| 数据处理 | 状态数据 |
| 帮助 | 使用帮助、工具 |

取消工程、前处理、状态管理、求解、工具独立页签。计算状态入口归入开始的工程组，工程树保留计算状态节点，明确一次计算对应一个状态。批量配置暂打开状态草稿，不假装已实现批量调度。运行入口沿用已有工作流权限控制，位于监控。

每个操作使用独立 SVG 资源，随 UI 静态库内嵌，不依赖网络或系统图标主题。已接入的入口有彩色图标；尚未接入的命令禁用，显示灰色图标和提示。帮助中的工具可恢复默认布局及打开工程、属性、输出面板。现有独立后处理工作台入口保留。

本次只改变主窗口布局和展示用语；不修改公共契约、状态持久化模型、批量调度或求解业务实现。所有中文界面字符串继续使用显式 UTF-16，避免目标 Windows 编译代码页影响。

## 自动检查与本地预览

`ui_window_integration` 检查五个页签、开始的四个分组、帮助中的工具组、每个 Ribbon 操作的图标可加载、计算状态说明、后处理窗口反复打开、服务重复绑定、运行权限及 Widget 所有权。

macOS 仅作兼容预览：在隔离的临时源码副本中将 Qt 精确版本改为本机 5.15.19，仓库正式 Qt 5.12.12 约束未改。构建成功，CTest 6/6 通过；检查主窗口截图，开始页各组与按钮未重叠，中文及图标正常。不能以此替代 Windows 基线验收。

## Windows 目标机验证

目标 `10.129.62.253`，项目 `F:\AeroSimWorkbench`，Qt 5.12.12 / VS2017 v141 x64 Debug。使用 `scripts\build-windows.cmd all Debug` 完成编译。CTest 4/6 通过：CLI、夹具、后处理 UI 和主窗口集成测试均通过；`gui_mock_smoke` 和 `postprocess_gui_mock_smoke` 的 offscreen 模式仍发生 SegFault（本次修改前已复现），不能宣称全套通过。

在用户交互桌面中改用原生 `windows` 平台运行主窗口和后处理 `--smoke`，两者 ExitCode 均为 0；主窗口 `--screenshot` ExitCode 为 0。人工检查截图：四个开始分组、大/小图标、中文标签正常显示。验证后重新启动新版主窗口，进程在桌面 Session 1 响应正常。原生启动通过不等同于 offscreen 问题已解决。

本地证据位于忽略的 `build-ui-preview/`：`ribbon-start.png`、`ribbon-build.log`、`ribbon-preview-result.txt`；目标机证据位于 `build-windows/` 下同名文件。当前 GUI 构建未启用正式 VTK Viewer，本次不作为三维显示验收。

Office 蓝色皮肤额外覆盖标题栏和 Ribbon 页签区域，使用类似 Word 的蓝色背景、白色未选中页签文字以及浅色当前页签；下方命令区保持浅色。集成测试检查标题背景、标题文字颜色、页签样式以及切换到其他皮肤时清除该背景。
