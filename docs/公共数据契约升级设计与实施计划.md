# 公共数据契约升级设计与实施计划

> 状态：PR 0 设计冻结版。本文冻结增量升级的语义、兼容边界和实施顺序；尚未加入代码的
> V2 类型仍是后续 PR 的目标契约，不应被描述为现有能力。
>
> 基线：`origin/main@0046652`、现有 `contracts/`、各模块 README，以及
> 《AeroSimWorkbench 软件界面操作逻辑说明》。

## 1. 范围和不变量

本次升级不改变 UI → Service → Infrastructure & Adapter 三层架构，也不实现真实工程持久化、
网格读取、求解器或后处理算法。公共 contracts 只保存跨模块必需的轻量引用、只读视图、命令、
事件和端口；完整业务模型继续由对应模块拥有。

冻结以下原则：

1. 第一版一个工作区对应一个 Project；沿用 `projectId`、ProjectManager 和工程目录命名，不新增
   `Workspace` 聚合或 `WorkspaceRef`。
2. ID 是聚合对象的稳定身份；revision 选择该对象的确定版本；schemaVersion 只描述持久化文件
   结构，三者不得互相替代。
3. 新 V2 Ref 的 ID 是不透明非空字符串，不要求调用方理解 UUID 或可读编号格式。
4. 新 V2 Ref 的 revision 从 1 开始。revision 0 表示未指定/legacy，不能用于启动正式计算。
5. 比较必须区分 `sameIdentity(a,b)` 和 `sameVersion(a,b)`：前者忽略 revision，后者包含 revision。
6. 跨线程 Qt 消息按值传递轻量类型并预先注册元类型；同步 Access 查询仅允许在 facade 所在线程
   调用，不得隐式执行文件 IO、哈希、网格解析或 VTK 操作。
7. 枚举持久化使用冻结的小写 snake_case token，不使用 C++ ordinal。
8. UI 的 `QVariantMap` 草稿、`MeshUiState`、postprocess drafts 仍是 Mock/UI 状态，不升级为正式
   持久化业务模型。

## 2. 当前契约与目标契约

| 领域 | 当前 | PR 目标 | 兼容方式 |
| --- | --- | --- | --- |
| 工程/工作区 | `ProjectRef` | 第一版保持一工作区一 Project | 不新增 Workspace 类型 |
| State/Case | `ScopeRef.caseId` | `StateRef(projectId,stateId,revision)` | caseId 只镜像 stateId，禁止独立身份 |
| 工作流步骤 | 单一 `StepState` | completion、validation、dependency block 分离 | legacy view 由 V2 单向派生 |
| 批处理 | planId/version + 模糊 batchId | `BatchPlanRef`、不可变执行快照、`BatchRunRef` | batchId 只按 legacy run ID 解释 |
| Task/Attempt | taskId + attemptId | Task 稳定身份、每次执行新 Attempt | 重试同 task；重新提交新 task |
| 网格 | 单个 `MeshRef`、`mesh(scope)` | 多 MeshDescriptor、唯一计算网格、独立 presentation | `mesh(scope)` 继续返回计算网格 |
| 资源 | kind/filePath 字符串 | typed resource、location、fingerprint | 新字段优先，旧字段双读写 |
| 日志/监控 | 缺 stream/attempt | stdout/stderr、update mode、attempt、sequence | legacy 默认 Application/AppendLine |
| 查询错误 | 默认空对象 | `AccessResult<T>` | 原接口保留，新接口结构化返回 |

## 3. Ref、ID、revision 与 schemaVersion

### 3.1 身份规则

目标引用及唯一身份如下：

| Ref | 对象身份键 | 确定版本键 | 有效性 |
| --- | --- | --- | --- |
| `ProjectRef` | projectId | projectId + revision | legacy 类型暂不收紧 |
| `StateRef` | projectId + stateId | identity + revision | IDs 非空、revision > 0 |
| `BatchPlanRef` | projectId + planId | identity + revision | IDs 非空、revision > 0 |
| `BatchRunRef` | projectId + batchRunId | identity；run 创建后不可变 | IDs 非空 |
| `TaskRef` | projectId + taskId | identity；Task 输入创建后不可变 | IDs 非空 |
| `AttemptRef` | TaskRef + attemptId | identity | TaskRef 有效、attemptId 非空 |
| `MeshRefV2` | projectId + meshId | identity + revision | IDs 非空、revision > 0 |
| `ResourceRefV2` | projectId + resourceId | identity + revision；fingerprint 校验该版本内容 | IDs 非空、revision > 0 |

`BatchRunRef` 不把 source plan 放进身份；`TaskRef` 不把 batchRunId 放进身份。来源关系是对象属性，
否则修复来源元数据会意外改变对象身份。

### 3.2 State 与旧 caseId

- 业务代码只创建 `StateRef` 身份；`caseId` 是兼容投影，值必须等于 `state.stateId`。
- 读取只有 caseId 的旧数据时，在已知 project scope 下构造 StateRef；revision 缺失时标为 legacy
  未指定，必须经 State 服务解析到确定 revision 后才能运行。
- 同时存在 stateId 和 caseId 且不一致时返回 `Conflict`，不静默选择任意一方。
- 新数据过渡期双写；新逻辑不得分别生成 stateId 和 caseId。

### 3.3 schemaVersion

Project、State、BatchPlan、BatchRun、Task、WorkflowSnapshot 分别拥有自己的 schemaVersion。
schemaVersion 不放入 Ref，也不参与对象身份。读取未知更高 schema 必须拒绝写回；迁移按显式
`vN -> vN+1` 进行。revision 是业务编辑版本，fingerprint 是内容身份，均不等于 schemaVersion。

## 4. 工作流状态模型

### 4.1 三个独立维度

```text
completion: NotStarted | InProgress | Completed
validation: NotValidated | Valid | Invalid | Stale
dependencyBlock: Unblocked | Blocked(blockers[])
```

`NotApplicable` 不是 completion。它由 workflow definition、solver mode 和 scope 派生为
`applicable=false`，并携带规则来源。

目标公共视图：

```cpp
enum class CompletionState { NotStarted, InProgress, Completed };
enum class ValidationState { NotValidated, Valid, Invalid, Stale };

struct DependencyBlockerView {
    QString dependencyStepId;
    QString code;
    QString message;
    QString targetPageId;
};

struct WorkflowStepViewV2 {
    QString stepId;
    ScopeRef scope;
    bool applicable = true;
    CompletionState completion = CompletionState::NotStarted;
    ValidationState validation = ValidationState::NotValidated;
    QVector<DependencyBlockerView> blockers;
    QString summary;
    QString targetPageId;
    quint64 factRevision = 0;
};

struct WorkflowViewV2 {
    ScopeRef scope;
    QString definitionVersion;
    quint64 viewRevision = 0;
    QVector<WorkflowStepViewV2> steps;
    QVector<WorkflowActionView> actions;
    QVector<ValidationIssue> issues;
    QString nextSuggestion;
};
```

### 4.2 持久化事实与派生状态

workflow 模块持久化：completion、最近一次校验结果、校验输入印章、definitionVersion、
factRevision 和时间。对应参数、网格、State、Task 的真实数据仍由各自模块持久化。

以下内容不作为事实直接持久化：Stale、blockers、action.enabled、nextSuggestion。它们在加载后由
当前 definition、当前输入 revision/fingerprint 和依赖事实重新计算。

| 触发 | completion | validation fact | 派生结果 |
| --- | --- | --- | --- |
| 新建 scope | NotStarted | 无 | NotValidated |
| 开始编辑 | InProgress | 保留 | 输入变化后 Stale |
| 专业模块成功保存 | Completed | 不自动通过 | NotValidated 或 Stale |
| 校验通过 | 不变 | Passed + input stamp | Valid |
| 校验失败 | 不变 | Failed + issues + stamp | Invalid |
| 上游改变 | 不回退 | 保留审计事实 | Stale；下游重算 blocker |
| 依赖阻塞/恢复 | 不变 | 不变 | 只改变 blockers |

异步校验提交时必须重新比较 scope、definitionVersion、参数 snapshot、资源 revision/fingerprint；
任一不匹配即丢弃旧结果。

### 4.3 V2 服务端口与兼容

V2 不新建第二个 QObject 状态源。后续 PR 在现有 `IWorkflowService` 上增量加入带默认 Unsupported
实现的同步 `viewV2(scope)`，并增加 `workflowViewV2Changed(WorkflowViewV2)` 信号。实现服务以 V2
事实为唯一来源，同时通过无状态 adapter 生成现有 `WorkflowView` 并继续发送旧信号。

legacy `StepState` 映射：blocked 优先映射 Blocked；Stale/Invalid 映射 NeedsValidation；Completed +
Valid 映射 Complete；其余映射 Pending。该映射不可反向持久化。

## 5. State、BatchPlan、BatchRun、Task 与 Attempt

### 5.1 对象关系

```text
Project
 ├── StateConfig 1..N
 ├── BatchPlan(logical planId, append-only revisions) 0..N
 │     └── ordered BatchPlanItem -> pinned StateRef
 ├── BatchRun 0..N
 │     ├── sourcePlan -> exact BatchPlanRef
 │     ├── executionPlanSnapshot -> immutable ResourceRef
 │     └── Task 1..N
 └── Single Task 0..N

Task
 ├── immutable TaskInputManifest
 ├── origin Single | Batch
 ├── StateRef
 ├── optional BatchRunRef
 └── Attempt 1..N
```

完整 StateConfig/BatchPlan 属于 configuration，BatchRun/Task/Attempt 属于 runtime，ProjectManager
保存索引和关联，WorkflowManager 读取事实而不复制状态机。

### 5.2 计划版本与历史恢复

- 编辑计划产生同一 planId 的新 revision，不原地覆盖被 BatchRun 引用的 revision。
- 启动批处理时，必须生成不可变 `BatchPlanExecutionSnapshot` 资源，包含 exact BatchPlanRef、按序
  plan items、固定 StateRef 及执行策略，并保存 fingerprint。
- BatchRun 同时保存 exact sourcePlan 和 execution snapshot ref。即使当前计划被继续编辑、删除或
  索引修复，历史运行仍能从 snapshot 恢复。
- 每个 Task 再保存自己的不可变 TaskInputManifest，至少固定有效参数 snapshot、计算网格
  revision/fingerprint、solver/backend 配置和来源 StateRef。
- 仅保存 `planId + 可覆盖 version number` 不满足恢复要求。

### 5.3 单次与批处理任务

- Single Task：origin=Single，不创建伪 BatchRun。
- Batch Task：origin=Batch，必须引用 BatchRunRef；source plan 通过 BatchRun 追溯。
- `TaskRecord.batchId` 在 legacy 读取中只解释为 batchRunId，不推断为 planId。
- `TaskCommand.batchPlanId/version` 始终表示准备执行的计划；runtime 创建 BatchRun 后才产生
  batchRunId。

### 5.4 Task 与 Attempt

- 一次 Task 固定一个 TaskInputManifest；Task 输入永不因工程编辑而变化。
- 同一 Task 的执行重试保持 taskId，创建新 attemptId。每个 attempt 的 sequence 从 1 单调递增。
- Pause/Resume 是同一 attempt 的控制过程，不创建新 attempt。
- Failed、Stopped、Cancelled 后，用户显式“重试”且输入完全不变时可创建新 attempt。
- Finished 后再次计算，或任何参数、网格、solver 输入发生变化时，创建新 taskId，不叫重试。
- attempt 的日志、监控和错误必须带 attemptId，防止曲线和输出混合。

终态冻结为 Finished、Failed、Stopped、Cancelled。Created、Queued、Preparing、Running、
PauseRequested、Paused、StopRequested、Cancelling、Reconciling 均为非终态。Unknown 仅用于无法
解释的 legacy/异常数据，不能作为新任务正常状态。

### 5.5 Stop 与 Cancel

| 命令 | 业务语义 | 请求后状态 | 成功确认终态 |
| --- | --- | --- | --- |
| Stop | 请求后端有序停止，允许其完成收尾/检查点 | StopRequested | Stopped |
| Cancel | 撤销排队任务或要求尽快中止，按后端策略清理 | Cancelling | Cancelled |

发出命令不等于成功。只有执行后端确认并且 runtime 已可靠保存状态后才发布终态事件。拒绝、不支持、
超时或异常退出分别保持原状态或转 Failed，并提供 errorCode。Stop 后的继续执行属于新 attempt，
不是 Pause/Resume。

### 5.6 TaskSnapshot 的最低信息

目标 TaskSnapshot 必须包含：TaskRef、origin、StateRef、可选 BatchRunRef、当前 attemptId、
TaskInputManifest typed resource、ParameterSnapshotRef、MeshRefV2、solver/backend ID、状态和时间、
typed log/monitor/result/checkpoint refs、错误、record revision。ParameterSnapshotRef 单独存在不足以
代表全部不可变执行输入，因此 TaskInputManifest 是恢复的权威清单。

## 6. 多网格模型

### 6.1 职责分离

| 类型 | 职责 | 是否改变计算几何 |
| --- | --- | --- |
| ResourceRefV2 | 文件/URI、类型、revision、fingerprint | 否 |
| MeshRefV2 | 确定 mesh 聚合及 revision | 否 |
| MeshDescriptor | 名称、角色、拓扑、维度、坐标系、单位、来源 | 否 |
| MeshTransform | 数据空间平移/旋转/单位转换；输出新 MeshRefV2 | 是 |
| MeshPresentation | visible、representation、颜色、opacity、displayScale | 否 |

当前网格界面的比例因子默认为 `MeshPresentation.displayScale`，只影响显示，不改变计算网格坐标、
revision 或 fingerprint。只有用户进入明确的几何变换/单位转换业务操作，才能创建 MeshTransform；
成功后产生新的 processed MeshRefV2，失败不发布半成品。

### 6.2 计算网格与显示网格

一个 scope 可枚举多个 MeshDescriptor；当前运行 scope 至多选择一个 computation mesh。UI 的“最多
10 个”是产品显示限制，不写进公共模型结构上限。参考网格、结果网格和辅助网格可以同时显示，
但不会自动成为求解输入。

旧 `IMeshAccess::mesh(scope)` 在兼容期固定解释为“当前计算网格”。新增只读查询提供 meshes、
meshDescriptor 和 computationMesh；import/remove/transform/selectComputationMesh 属于异步业务服务。

### 6.3 MeshPresentation 持久化

MeshPresentation 是 Project 内的场景偏好，建议由 visualization/scene 保存到工程内独立场景文档，
关联 projectId、meshId 和 viewport/scene ID。它与网格资源和计算输入分离，也与全局 QSettings 分离。

QSettings 只保存窗口几何、Dock、splitter、主题等用户布局；不得保存业务网格身份或工程场景。
删除/找不到网格时保留可诊断的 dangling presentation 或由显式清理流程处理，不静默套用到同名网格。

## 7. 资源、文件、fingerprint 和遥测

### 7.1 资源位置

`ResourceLocation` 区分 ProjectRelative、ExternalAbsolute、Uri。工程内部优先保存相对工程根目录
路径并禁止 `..` 逃逸；外部路径显式标记并保存 fingerprint。URI 是预留标识，不表示已经支持网络
读取。

`ContentFingerprint` 至少包含 algorithm、digest、sizeBytes 和辅助 modifiedAt。mtime 不能单独证明
内容相同。算法 token 初步采用 `sha256`；实际计算时机和大文件优化留待 project/data adapter PR。

### 7.2 typed resource

Resource type 使用稳定枚举/token，例如 project_file、parameter_snapshot、task_input_manifest、
batch_plan_snapshot、mesh、result、log、monitor、checkpoint、export。旧 kind/filePath 兼容读取；新字段
与旧字段冲突时返回 Conflict。

### 7.3 日志和监控

LogEntryV2 增加 projectId、taskId、attemptId、sequence、stream(Application/Stdout/Stderr) 和
updateMode(AppendLine/AppendChunk/ReplaceCurrentLine)。MonitorSampleV2 增加 attemptId，并允许
MonitorBatch 批量传递。

runtime 负责有界缓冲、限频、降采样和完整原始记录落盘。关键 TaskEvent 与高频日志/监控分流，
不能因为 UI 降采样丢失任务终态。

## 8. 数据访问和端口

### 8.1 统一规则

- Access/Query：同步、只读、轻量、同线程，返回值副本。
- Service command：可能修改状态或耗时，异步执行并通过 queued event/report 返回。
- 查询错误使用 `AccessResult<T>`，区分 Ok、NotFound、InvalidArgument、Conflict、StaleRevision、
  Unavailable、Unsupported、IoError、InternalError。
- 业务能否执行继续使用 ValidationResult；查询成功不等于业务校验通过。

### 8.2 增量接口

现有纯虚接口不删除、不改签名。为避免一次性破坏 Mock，新增 Query 可以先作为并列非 QObject
接口，通过 ServiceBindings 的 nullable pointer 注入：

- IProjectQuery：project、findResource、resources、states、batchPlans。
- IStateQuery/IParameterQuery：state(s)、snapshot、validateSnapshot。
- IMeshQuery：meshes、meshDescriptor、computationMesh。
- IResultQuery：result、resultsForTask、resultsForState。
- ITaskQuery：task、queryTasks、batchRun。

写操作保留在各模块业务 Service，不把 IProjectAccess 或 DataAccess 变成 God interface。

### 8.3 必须保持的旧接口

- IWorkflowService::view/requestRun、两个现有信号和 onTaskEvent。
- ITaskService::record/handleTaskCommand/taskEventOccurred。
- IProjectAccess::currentProject/resource。
- IParameterAccess::validateParameters/currentSnapshot。
- IMeshAccess::validateMesh/mesh。
- IResultAccess::validateResult。
- IWidgetHost、WidgetSlot、ServiceBindings 现有字段。
- DatasetRef、SceneObjectRef 的 identity-only 语义。

仓库统一重编译，因此不承诺二进制 ABI；承诺兼容期内的源码调用和持久化迁移路径。

## 9. 头文件依赖设计

为避免循环引用，目标依赖保持为：

```text
References.h          Qt Core 轻量 Ref；不包含业务 Models
AccessResult.h        独立模板；不包含业务 Models
MeshModels.h          -> References.h
ExecutionModels.h     -> References.h
TaskModels.h          -> References.h, MeshModels.h, ExecutionModels.h
Telemetry.h           -> References.h
WorkflowModels.h      -> References.h, ExecutionModels.h
DataAccess.h          -> AccessResult.h + 所需轻量 Models
TaskPorts.h           -> TaskModels.h, WorkflowModels.h
IntegrationPorts.h    -> DataAccess.h, TaskPorts.h
```

References.h 不得反向包含 Task/Mesh/Workflow。TaskSnapshot 使用 MeshRefV2 时由 TaskModels 包含
MeshModels，不把 MeshRefV2 再塞回 References。所有公共头必须能作为一个翻译单元的第一个 include
独立编译，PR 0 已建立对应测试。

新 Core contracts 不使用 QColor 或 Qt Widgets；颜色采用 Core-only RGBA 值，在 UI/scene 边界转换。
代码只使用 C++14 和 Qt 5.12 可用 API，不使用 std::optional、std::variant 或 C++17 inline variables。

## 10. 稳定枚举 token

PR 0 冻结现有枚举的 v1 token 清单：

- IssueSeverity：info、warning、error。
- StepState：pending、needs_validation、complete、blocked。
- TaskCommandType：start、pause、resume、stop、cancel。
- TaskEventType：prepared、started、status_changed、progress_updated、residual_updated、log_generated、
  warning、failed、finished、result_generated。
- TaskStatus：unknown、preparing、running、paused、finished、failed、cancelled。
- LogLevel：debug、info、warning、error。

PR 0 只建立测试清单，不添加生产 serializer。V2 枚举在其类型实现 PR 中追加 token 和真实 round-trip
测试；旧 token 不重命名。

### 19.2 遥测类型收敛

PR #12 收尾时核对确认：`Telemetry.h` 的旧 `LogEntry`（`timestamp`/`level`/`source`/`taskId`/`message`）

保留的类型：`LogLevel`（V2 类型继续使用）、`ErrorInfo`（没有 V2 对应物，仍是日志/错误控件与
数据校验失败共用的通用错误报告，见 `PostProcessContracts.md`、`PostProcessIntegrationGuide.md`）。
